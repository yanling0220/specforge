# T4.7 代码审查视图：首版范围与验收

> 2026-11-18 · Codex（GPT-6）。范围方案已交付，T4.7 `verify`，待用户选择实施；下列接口、视图和验收用例均为计划，尚未实现。T4.5e 真实飞书验收按用户要求暂缓，不作为依赖。进度以 [TASKS.md](TASKS.md) 为准。

## 1. 目标与推荐范围

开发者在同一页面核对“这次提交改了什么、已有审查说了什么、各项 AC 有哪些明确关联”，再进入现有门禁页查看证据和签字。首版新增 change 详情的「代码审查」标签，路由 `#/changes/<id>/review`，仅提供读取、筛选、刷新和跳转。

推荐交付三个部分：

1. **当前提交差异**：change 的 `baseSha` 到读取时捕获的完整 HEAD SHA，文件列表与按需加载的统一 diff。
2. **已有审查记录**：当前 SHA 的最新 agent / human 记录、G6B 的检查结果，以及可展开的原始历史报告。
3. **AC 追溯表**：该 SHA 的规格位置、任务中的明确 AC 关联、测试文件中的 AC 编号引用、审查声明和引擎证据入口，分别展示。

首版不新增模型调用、验证执行、审查写入、行内代码评论、发现项解决状态、个人指派或自动推进。签字、打回和审批仍在现有门禁页；产物评论仍在现有产物审阅器。没有 GitHub / GitLab 集成，不提供任意仓库文件浏览或历史提交比较。

## 2. 页面与提交语义

页面顺序为：提交范围及刷新状态 → 当前审查摘要 → 文件列表与 diff → AC 追溯表 → 历史报告。窄屏使用上下布局，不引入编辑器依赖。代码、路径和报告文本按纯文本转义展示。

- **范围**：使用两个提交树的 `baseSha..targetSha` 差异；不改用 merge-base / 三点 diff。HEAD 是当前项目仓库的 HEAD，不按任务 trailer 猜测归属。范围可能含其他 change 的提交，页面明确提示不能据此认定文件由本任务实现。
- **版本**：仅在 `implement / closing / delivered` 展示提交视图；之前提示“进入实现阶段后可查看提交审查”，不把未提交材料与提交 diff 混合。delivered 仍按读取时 HEAD 展示，与现有门禁语义一致；不声称冻结了交付 SHA。
- **工作区**：暂存、未暂存和未跟踪改动均不进入 diff 或 AC 追溯；提示未提交改动未纳入，OpenSpec 改动沿用既有提示。`baseSha === targetSha` 且读取成功时显示“两个提交相同，无差异”，与读取失败区分。
- **基线**：缺失基线 / HEAD 对象或 Git 读取失败时，差异区域不可用。基线不是目标祖先时仍允许两个树比较，但显著标记“基线不在当前历史中”；不得称为新增提交集合、完整交付审查或自动换基线。
- **动作**：提供“查看门禁 / 签字”和已有证据页链接。跳转后重新读取当前状态。现有签字绑定操作时 HEAD，没有客户端 `expectedSha` 契约；本功能不承诺“签的必然是刚才浏览的 SHA”。若要在本页签字，须另行设计服务端原子版本校验，不能只增加前端确认框。

## 3. 已有数据能支持什么

| 内容 | 权威来源及首版规则 | 不作出的推断 |
|---|---|---|
| 文件差异 | Git 中基线与目标两个树；新增 / 修改 / 删除 / 类型变化；显示模式、路径和可用的文本 diff | 不从工作区补文件，不声称任务级归属 |
| 当前审查 | `ReviewRecord[]` 中 `sha === targetSha`，按原数组写入顺序分别取最后一条 agent / human；G6B 复用 `evaluateReview` | 不按 `at` 排序选生效记录，不取任意旧 pass 抵消新 fail |
| 发现项 | 保留 severity、kind、anchor、text；阻塞与非阻塞分组，标出缺失字段 | anchor 没有文件行号契约；不把文字猜成代码位置，不把后续 pass 当作逐项已解决 |
| 审查范围回执 | 原样显示 `coverage`，只有精确匹配已知 AC ID 的条目才加入相应 AC 行 | 声明不是引擎证据；文件名或自然语言不自动折算为 AC 覆盖 |
| AC 与任务 | 目标提交中的 `specs/**/spec.md`、`tasks.md`，复用 `parseSpec / parseTasks`；展示需求 / 场景标题、规格路径及行号、任务 ID 和勾选状态 | 勾选任务不证明代码实现；任务数据没有可靠的代码文件归属 |
| 测试引用 | 目标提交中匹配当前 `testGlobs`、包含字面量 `[AC-n]` 的测试文件；与既有 `acCoverage` 判定口径一致，使用能区分错误的有界读取 | 编号引用不是逐 AC 执行结果、行为覆盖或行覆盖率，不展示“AC 测试通过” |
| 验证 / TDD | `Store.evidenceIndex` 及已有证据页；显示 SHA、任务、记录顺序、结果和 `hashOk` | 缺失 / 哈希不符的证据不可采信；旧 SHA 验证不支持当前 SHA，G5 祖先证据不冒充当前提交重跑 |

### 当前与历史报告

当前摘要展示原 verdict、审查者、时间、coverage、findings、note 及是否参与当前 G6B。agent verdict=pass 但 coverage 为空或存在 blocking 时，原报告仍显示 pass，旁边明确展示引擎检查失败；不覆盖原文或修改门禁规则。human 签字沿用现有 G6B 判定，不另外发明覆盖要求。

同 SHA 较早的记录标为“已被同类后续记录替代”，其他 SHA 标为“历史提交，未用于当前门禁”。无当前记录显示“当前提交尚无审查 / 签字”，历史报告仍可查。`ReviewRecord` 没有稳定 ID、历史 baseSha 或文件行锚点；首版使用快照内的记录序号作为显示键，不迁移旧状态、不回填字段。历史报告只显示其原 SHA 和原始内容，不以当前基线重建当年的 diff，也不把历史 AC 锚点跳到当前规格。

### AC 追溯表

一行对应“规格路径 + 场景行号 + AC ID”，不能仅用 AC ID 合并同名场景。重复编号显式标记歧义；共享同一编号的任务 / 测试引用只说明编号匹配，不能证明对应到哪个场景。缺规格、无 AC、缺任务或零引用都显示明确的空状态，不生成百分比或绿色“全部覆盖”。S 档没有 AC 时仍可查看 diff 和审查，不新增门禁要求。

关联 findings 时，仅将当前记录中精确匹配唯一 AC 的 anchor 放入该行；精确 Q 编号可以链接当前问题，注明这是当前问题页面，报告没有冻结答案版本。未知、含混、文件名或自然语言 anchor 原样保留在报告中。不能由文档里出现 Q 编号推断某个 AC 与该 Q 的逐项关系。

证据位于独立区：列出目标 SHA 的验证、基线验证，以及任务对应的 G5 证据入口并标明各自 SHA / 哈希状态；G5 是否满足仍交给既有门禁。AC 行可跳到该证据区，但不得伪造“某份全量通过报告证明此 AC 已单独执行”的关联。

## 4. 读取快照与接口草案

所有接口沿用当前项目的鉴权、索引可用性和仓库锁。逻辑分层：runner 做有界 Git 读取；core 生成当前 / 历史分类和追溯映射；Store 校验文件权威状态并组合快照；server 返回 DTO；Web 负责展示。无需数据库迁移、额外持久化缓存或修改 `ReviewRecord`。

| 接口（项目内相对路径） | 计划返回 |
|---|---|
| `GET /api/changes/:id/review` | 可用阶段、baseSha / targetSha、快照版本、未提交提示、基线关系、受限文件清单、当前 / 历史报告、G6B 检查、AC 追溯、证据目录及各区域状态 |
| `GET /api/changes/:id/review/files/:fileId?snapshot=<version>` | 在重新鉴权并验证版本后，返回清单中该文件的模式、状态、统一 diff 或不可展示原因 |

请求不接收任意仓库 root、SHA、Git ref 或文件路径。`fileId` 由引擎根据项目仓库绑定、change ID、两个提交和清单条目生成，仅索引当前 change 的允许条目；未知 ID 返回 404，不能借此读取清单外文件或另一个项目。快照版本不是授权凭据。

Store 持同一仓库锁核对日志链、相关状态、用户名册、已有锚定和 pending 状态，捕获目标 HEAD，再读取提交材料与证据目录；已有“尚未锚定”状态不被本功能当作损坏，也不自动创建锚定。读取结束复核 HEAD，发现变化返回 `409 review_stale`，不拼接两版材料。仓库锁只协调平台进程，不能阻止外部 `git commit / checkout`。

快照版本绑定项目仓库、change、baseSha、targetSha、业务事件链头、相关配置（含 `testGlobs`）和所展示证据的有效性。文件请求重新取得并校验这些条件；HEAD 未变但新审查、配置或证据改变，同样要求刷新。版本变化时清空已加载 diff、旧报告分类和 AC 映射，重新读取快照，不把旧文件响应装入新页面。版本计算排除读取时间，避免无变化时持续失效。

失败按区域表达：审计 / 状态 / 仓库异常使整个视图不可用；Git diff 超限或单文件不可读可以保留已验证的报告区，但对应区域必须显示不可用 / 未完整读取。测试引用读取失败不得显示为“无引用”。不得用 `200 + 空数组` 掩盖失败，原始 Git stderr、服务器绝对路径和配置正文不直接返回浏览器。

## 5. Git 读取与展示边界

现有 runner 的 `git / changedFiles / readFileAt / grepFiles` 使用宽松限制、换行切路径或将异常折为空；首版不能直接将这些助手作为 HTTP 任意读取通道。新增只读助手及测试，保持既有 CLI / 门禁语义。

- 只使用参数数组调用 Git，不拼接 shell。先将内部基线和 HEAD 解析为完整 commit SHA，随后每条命令使用捕获的 SHA。清理影响仓库选择的 Git 环境变量，固定仓库；使用 `--no-ext-diff / --no-textconv` 并禁用 pager、颜色和子模块递归，设置 `GIT_OPTIONAL_LOCKS=0` 避免只读状态查询刷新 index，设置 `GIT_NO_LAZY_FETCH=1` 禁止缺失对象触发隐式下载；不执行项目脚本或取回远程对象。
- 文件清单采用 NUL 分隔、保留原始路径；后续路径按字面量传递，不能让 `:(...)`、`*` 或前导短横线变成 pathspec / 参数。空格、中文、制表符、换行和 HTML 字符安全转义。无法无损表示的路径显式标为不可展示，不悄悄读取替代路径。
- 首版固定关闭重命名 / 复制检测，重命名显示删除和新增，避免相似度计算与跨页配对歧义。统一 diff 带旧 / 新行号和固定三行上下文；删除文件展示旧侧，新增展示新侧。
- 二进制仅显示状态与可取得的大小；符号链接只显示对象类型和链接目标文本，不跟随；gitlink 只显示前后对象 SHA，不进入子模块或联网。文本无法解码时标为不可展示，模式变化独立显示。
- `.git/`、`.specforge/` 的内容不经代码接口输出，包括被错误跟踪的历史文件；统计中说明有内部路径被排除，不把排除后的空列表称为仓库无改动。OpenSpec 可作为普通提交文本显示。不存在通用下载或完整文件接口。
- 默认每次 Git 子进程最长 5 秒、单请求 Git 读取累计最长 15 秒；文件清单最多 1,000 条、输出最多 2 MiB，单文件 patch 最多 256 KiB、单次 JSON 响应最多 4 MiB。文本材料、AC 扫描与报告组装也受响应 / 读取预算约束。超限中止并标明范围，不能把被截断的半个清单或 patch 当成完整结果，也不能为了限制输出先无界读入内存。首次清单超限时提示改用本地 Git；完整计数取不到就不显示虚假总数。

限制用明确状态区分 `binary / symlink / submodule / excluded / too_large / unavailable`，不把每个特殊对象都显示成普通空 diff。后台轮询不预取所有 patch；选择文件后才加载，降低持锁时长。超时 / 超限只读退出，不写错误审查或业务事件。

## 6. 权限、刷新与操作边界

- 复用当前项目的读取权限：已启用名册时必须登录且账号有效；dev / product 均可查看，管理员身份不额外授予签字权限。未启用名册的旧单项目仍沿用仅本机只读访问。首版不新增按文件 / 角色限制源码的权限模型，部署者应将现有项目读取权限视为允许查看范围内代码。
- 多项目使用现有 `/p/<id>/api/...` 和完整文档切换；部署前缀由现有 URL 助手生成。A 会话、文件 ID、相同 change ID 或快照不能用于 B；项目损坏不回退到其他项目。
- 手动刷新、现有 WebSocket 事件刷新，以及 15 秒补查捕获没有业务事件的 HEAD 变化。复用现有同文档请求串行与有界忙重试；业务操作不自动重放。请求身份 / 项目失效时清空代码和报告，重新登录。
- 刷新发现新快照或读取失败后移除旧 diff 和“当前通过”摘要，显示刷新要求或错误；迟到的旧请求不得覆盖新快照。短暂显示上一次成功内容时也必须明确版本和加载状态，不称为实时。
- 页面读取不创建审查记录、已读状态、证据、锚定或通知。既有服务独立定时锚定 / 通知不属于页面动作；只读验收时关闭这些后台任务以隔离因果。

## 7. 主要取舍

| 选择 | 推荐及优点 | 代价 / 后续方向 |
|---|---|---|
| 统一 diff / 双栏编辑器 | 首版统一 diff；依赖少，适合窄屏，可直接对应 Git 输出 | 大改动横向比较较弱；必要时再加双栏 |
| 整个提交范围 / 按任务归属 | 基线到当前 HEAD；来源明确，与现有审查输入一致 | 含并行 change 的改动；任务归属需另有可靠数据 |
| 当前 diff / 历史 diff | 首版当前 diff，保留历史报告 | 无法还原未记录的历史审查基线；不猜测当年范围 |
| 明确追溯 / “覆盖率” | 分列规格、任务、测试引用、声明、证据 | 阅读者需结合证据判断；不提供无依据的完成百分比 |
| 只读 / 在本页写入 | 首版跳转既有门禁操作；避免复制流程和权限逻辑 | 多一步跳转；本页签字须先补原子 SHA 绑定契约 |

以下均为计划，当前文档交付不代表通过。新增自动测试使用临时 Git 仓库、ScriptedAdapter 或注入客户端；不调用真实模型、发送 IM 或要求恢复 T4.5e。

| T47-AC-06 | 当前 / 基线验证与任务 G5 证据标明各自 SHA；缺失或哈希异常明确不可采信，旧验证不替代新验证；可打开已有证据页，不生成逐 AC 执行结论 |
| T47-AC-07 | 用同步屏障制造读取中 HEAD 改变、快照后新增审查 / 改配置 / 破坏证据，旧文件请求得到 stale 或不可用；新旧请求反序到达不混版。无变化刷新不改变快照版本 |
| T47-AC-08 | 未登录、停用 / 重置令牌、A 会话访问 B、同名 change / 文件及带部署前缀的接口均沿用隔离契约；product 可读但不能签字，损坏项目失败关闭且健康项目可用 |
| T47-AC-09 | 超时、文件清单 / patch / JSON 上限及 Git 异常均有可识别状态，不泄露 stderr 或把部分结果当完整成功。配置 external diff / textconv 哨兵确认没有被执行；无远程取回或子模块命令 |
| T47-AC-10 | GET 前后对比 HEAD、index / 工作区、业务状态、日志链、名册、证据和发送账本指纹保持；无 agent / verify / signoff 调用。锚定未配置可读，链 / 状态 / pending 损坏不可读，不能自动修复 |
| T47-AC-11 | Web 可进入审查标签、选择文件、筛选发现项 / AC、展开历史、跳到门禁 / 证据；手动 / 事件 / 15 秒补查后正确刷新，错误清空旧结论；切换项目、退出和迟到响应不残留另一项目代码 |
| T47-AC-12 | 真实 Chrome 在根路径单项目、带前缀双项目完成审查读取、外部提交刷新、失败恢复、历史 / 证据跳转及项目隔离；回归现有收件箱、本人确认和门禁签字流程，链 / 状态一致。新实现的 typecheck、全量测试和 Web 构建通过 |

## 9. 分步研发与完成标准

T4.7 是本次范围设计，维持原任务含义；实现另列 T4.7a～d。用户选择实施本方案后将 T4.7 改为 done，并按顺序开始，不将本方案视为功能已上线。
