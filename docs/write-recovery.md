# 仓库锁与写入中断恢复（T4.3c）

## 1. 保护范围

CLI、HTTP、Store 复合操作、用户名册、证据、OpenSpec 生成产物和事件写入使用同一仓库锁；模型调用、验证与 Git worktree / 合入等长操作也持锁到完成。锁位于 Git common dir 的 `specforge-write.lock/`，真实路径别名和共享 Git 元数据的 worktree 共用；不同仓库独立。可用 `git rev-parse --git-common-dir` 查询位置。

锁通过本机文件系统原子建目录获取，记录 PID、随机令牌和开始时间。同一次操作内部允许同步 / 异步嵌套；独立操作立即拒绝争用，不排队、不自动重试。HTTP 返回 `409 write_busy`，CLI 失败退出，没有执行回调或写入成功事件。为避免读到多文件替换的中间状态，读请求也参与锁；长任务期间同仓库查询可能暂时返回忙。接收 HTTP 正文时尚不持锁。

这里只支持单服务器、本地文件系统、所有写入口遵守本协议的部署。不提供多节点 / NFS 协调、恶意进程隔离，也不能阻止用户直接执行 Git 或编辑文件。工作区和仓库备份仍由管理员负责。

## 2. 文件写入边界

引擎先在 common dir 写入 `specforge-write.pending.json`，记录原仓库真实路径、操作涉及文件的写前 / 写后哈希（不存在为 null）；合入还记录 HEAD。随后逐文件以临时文件、文件 fsync、rename 替换，最后替换完整的 `events.jsonl`，成功后删除 pending。删除产物也纳入快照。不会把半行 JSON 当作有效事件。

这不是多文件数据库事务：进程可能在任意两次替换之间退出。普通 IO 错误即使正常释放锁，pending 仍会阻断后续操作；进程被杀死则保留锁。实现不提供自动回滚 / 重放，也不承诺断电、内核崩溃或磁盘损坏后的持久性（未对目录执行 fsync）。本文和自动故障测试的保证范围是进程中断。

一项复合命令可能产生多条各自完整的事件。前面的事件已经成功、后面的操作失败时，不能把整项命令当成从未执行；先查看实际事件和状态，再决定剩余动作。网络响应丢失也不等于写入失败，不能盲目重发业务请求。

## 3. 查看与安全恢复

先暂停该仓库的人工操作，保留源文件、证据、Git 元数据、锁和 pending 的备份，在原项目目录运行：

```bash
sf lock status
sf lock recover --reason "已核对中断现场及可信备份"
```

`status` 不需要获取业务锁，输出 owner、alive、recoveryClaimed、pending。锁的 PID 仍存活时，恢复命令拒绝抢占；PID 被系统复用也保守地按活锁处理。不能只凭锁的年龄判断失效。

已知持锁进程退出后，普通请求返回 `503 recovery_required`；引擎不会自动删锁。显式恢复在原锁内独占申请 recovery 子目录，核对事件链、用户名册、所有 change 状态哈希和已有 Git 锚定；存在 pending 时，还必须在原仓库完全匹配**写前全部文件**或**写后全部文件**。混合结果不通过，即使状态哈希看似一致，未入链的证据或产物也不能略过。

通过后保存本机 `specforge-recovery.json` 回执，再清除 pending 和中断锁。回执不是哈希链里的业务成功事件，不证明原命令执行成功；恢复不会补造成功事件、重放操作或执行 `log ack`。恢复失败保留保护，先处理不一致再重试。

## 4. 不能自动恢复的情况

- **部分文件已写**：保持停写，根据可信备份、事件记录与 pending 的全部路径 / 哈希，离线还原完整写前快照或核对完整写后结果。pending 只记录哈希，不包含原文件内容；没有备份不能凭它恢复内容。不要编辑 pending / 事件链来伪造匹配，也不要用 `sf log ack` 掩盖中断。
- **Git 已合入但事件未写**：单独恢复 HEAD 不足够。必须核对并恢复 HEAD、工作区、暂存区和 Git 遗留锁；恢复命令会拒绝未核对的脏工作区 / 暂存区及 index.lock、HEAD.lock、MERGE_HEAD。先保存实现提交 SHA 与现场，不要对有用户改动的仓库盲目执行 reset。独立 worktree 的遗留目录也需人工核对清理。
- **owner 缺失 / 无效**：建锁和解锁瞬间可能暂时没有 owner，因此普通调用按忙拒绝。若持续存在，或写 owner 时进程退出，无法自动证明锁已死。先停止该仓库全部 server、CLI、agent 与恢复进程，确认不存在写入者并完整备份现场，再由管理员离线移走未知锁目录；**保留 pending**，之后仍需运行显式恢复核对。不要在线删除或替换锁。
- **恢复进程也退出**：recovery 子目录可能残留。仍需停止全部写入者、确认无恢复进程、备份，再离线移走该 recovery 子目录；保留原锁、owner 与 pending，重新运行恢复。
- **源文件 / 日志 / 锚定损坏**：从可信备份和独立保存的审计锚定恢复；不得自动确认带外修改或把空日志视为恢复成功。管理员拥有文件写权限不代表修改后的记录可信。

解除保护后先检查 `sf log verify`、状态与相关证据，再恢复服务 / 重连订阅。只有明确被 `write_busy` 拒绝且未执行的操作才适合直接重试；已经开始写入或响应不确定的操作必须先核对结果。
